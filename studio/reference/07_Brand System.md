# Purpose

The Brand System defines how the Studio presents itself visually and verbally.

Its purpose is to ensure every product, document, website, repository, screenshot, report and customer interaction feels like it comes from the same organisation.

Consistency builds trust.

The brand should evolve deliberately rather than accidentally.

---

# Brand Philosophy

The Studio exists to build practical digital products that solve real operational problems.

The brand should communicate:

* competence
* trust
* clarity
* professionalism
* practicality
* craftsmanship

The Studio should never appear flashy, trendy or overly corporate.

Confidence should come from quality rather than marketing.

---

# Brand Personality

The Studio is:

* Calm
* Thoughtful
* Analytical
* Practical
* Reliable
* Professional
* Curious
* Human

The Studio is **not**:

* Loud
* Sales-driven
* Corporate
* Overly technical
* Humorous for the sake of attention
* Trend-chasing

---

# Brand Values

Every public product should reflect these values.

* Solve real problems.
* Build with care.
* Earn trust.
* Prefer simplicity.
* Respect users.
* Document decisions.
* Continuously improve.

---

# Positioning

The Studio creates lightweight operational systems that help individuals and organisations work more effectively.

Products should feel:

* approachable
* dependable
* easy to adopt
* professionally engineered

The Studio is not positioned as:

* an enterprise software company
* a consultancy disguised as software
* an AI company
* a startup chasing rapid growth

---

# Audience

Primary audiences include:

* sports organisations
* clubs
* federations
* competitions
* sports businesses
* coaches
* analysts
* administrators

Secondary audiences include:

* small businesses
* educators
* personal productivity users
* spreadsheet enthusiasts

Products should remain understandable by non-technical users.

---

# Tone of Voice

Writing should be:

* clear
* concise
* respectful
* evidence-based
* practical

Avoid:

* hype
* exaggerated claims
* unnecessary jargon
* aggressive marketing
* artificial urgency

Explain rather than persuade.

---

# Writing Style

Use:

* British English
* short paragraphs
* descriptive headings
* consistent terminology
* active voice

Prefer clarity over cleverness.

Documentation should read like professional engineering documentation rather than promotional copy.

---

# Visual Principles

Every visual asset should feel:

* clean
* spacious
* balanced
* readable
* calm

Visual hierarchy should always be obvious.

Whitespace is a design tool, not empty space.

---

# Colour Philosophy

Colours should communicate trust rather than excitement.

Preferred characteristics:

* muted
* warm
* neutral
* accessible
* professional

Avoid:

* overly saturated palettes
* excessive gradients
* visual clutter

Individual products may introduce accent colours while remaining recognisably part of the Studio.

---

# Typography

Typography should prioritise readability.

Characteristics:

* modern
* neutral
* accessible
* highly legible

Avoid decorative display fonts except where intentionally justified.

---

# Iconography

Icons should be:

* simple
* consistent
* recognisable
* functional

Avoid mixing multiple icon styles within the same product.

---

# Imagery

Prefer:

* authentic screenshots
* diagrams
* workflows
* clean illustrations
* realistic product visuals

Avoid:

* generic stock photography
* decorative imagery
* AI-generated visuals that appear artificial
* visual noise

Images should support understanding.

---

# Product Naming

Product names should be:

* descriptive
* memorable
* easy to pronounce
* easy to search

Avoid:

* unnecessary abbreviations
* trendy spellings
* excessive punctuation

Names should communicate purpose before creativity.

---

# Documentation Style

Documentation should appear:

* structured
* consistent
* professional
* easy to navigate

Every document should follow Studio documentation standards.

---

# Screenshots

Product screenshots should:

* use realistic data
* avoid clutter
* demonstrate value
* maintain consistent spacing
* highlight important workflows

Screenshots are part of the product experience.

---

# Marketing Assets

Marketing should educate before selling.

Preferred assets include:

* annotated screenshots
* workflow diagrams
* comparison tables
* feature summaries
* short demonstrations

Avoid exaggerated promises.

Demonstrate value through evidence.

---

# Product Packaging

Every released product should feel complete.

Packaging should include:

* professional cover image
* documentation
* example data
* release notes
* licence
* version information

Users should immediately recognise a Studio product.

---

# Brand Consistency

Every product should feel like it belongs to the same family.

Consistency should exist across:

* documentation
* GitHub repositories
* websites
* checkout pages
* screenshots
* PDFs
* videos
* presentations

The Studio's reputation will not be built by its logo or colour palette.

The Brand System exists to ensure that quality is communicated clearly, professionally and consistently whenever someone encounters the Studio.
