# Purpose

The Design System establishes the visual, structural and interaction principles that define every Studio product.

It ensures products remain visually consistent, professionally presented and immediately recognisable regardless of the technology used to build them.

The Design System applies equally to spreadsheets, dashboards, reports, documentation, websites and future applications.

---

# Design Philosophy

Good design is functional.

Its purpose is to improve understanding, reduce cognitive effort and build trust.

The Studio values clarity over decoration.

Products should feel calm, intentional and reliable.

---

# Design Principles

Every product should be:

* Professional
* Practical
* Beautiful
* Calm
* Lightweight
* Accessible
* Trustworthy

Visual consistency is more valuable than visual novelty.

---

# Simplicity

Every interface should communicate its purpose immediately.

Users should understand:

* where they are
* what they should do
* what matters most

Avoid visual clutter.

Remove anything that does not improve understanding.

---

# Progressive Disclosure

Do not present every option immediately.

Show:

essential information first

advanced functionality only when required

Users should never feel overwhelmed.

---

# Visual Hierarchy

Every screen should clearly communicate priority.

Order information by importance.

Primary

↓

Secondary

↓

Supporting

↓

Reference

Nothing should compete equally for attention.

---

# White Space

White space is functional.

It separates ideas.

Improves readability.

Reduces cognitive load.

Do not fill empty space simply because it exists.

---

# Typography

Typography should prioritise readability.

Preferred characteristics:

clean

modern

neutral

professional

Limit the number of font sizes.

Maintain consistent spacing.

Avoid decorative fonts.

---

# Colour Philosophy

Colour communicates meaning.

Do not use colour as decoration.

Colour should indicate:

status

importance

interaction

feedback

Consistency is more important than variety.

---

# Colour Usage

Prefer restrained palettes.

Accent colours should guide attention rather than dominate the interface.

Use colour intentionally.

Never rely solely on colour to communicate important information.

---

# Layout

Layouts should feel structured and balanced.

Prefer:

grids

consistent margins

predictable spacing

logical grouping

Users should not need to search for information.

---

# Tables

Tables are one of the Studio's primary communication tools.

Tables should:

prioritise readability

avoid excessive borders

use subtle row separation

right-align numbers

left-align labels

maintain consistent spacing

Tables should communicate information rather than resemble databases.

---

# Dashboards

Dashboards support decisions.

They are not collections of charts.

Every dashboard should answer a small number of important questions.

Remove visualisations that do not support decision-making.

---

# Charts

Charts should emphasise interpretation rather than decoration.

Prefer:

simple

readable

labelled

consistent

Avoid:

3D charts

unnecessary gradients

chart overload

misleading scales

---

# Forms

Forms should minimise effort.

Ask only for information that is genuinely required.

Reduce typing wherever practical.

Support mobile use whenever possible.

---

# Navigation

Users should always know:

where they are

where they can go

how to return

Navigation should remain consistent across products.

---

# Documentation Design

Documentation should follow the same visual philosophy.

Readable.

Scannable.

Structured.

Avoid large uninterrupted blocks of text.

---

# Spreadsheet Design

Spreadsheets are products.

Not worksheets.

Users should not interact directly with formulas unless necessary.

Separate:

inputs

processing

outputs

documentation

Complexity should remain hidden.

---

# Dashboard Pages

Every dashboard should prioritise:

Key Metrics

↓

Important Trends

↓

Detailed Analysis

↓

Supporting Information

Do not overwhelm users with excessive statistics.

---

# Reports

Reports should communicate decisions rather than raw data.

Each report should answer:

What happened?

Why?

What should the user do next?

---

# Empty States

Products should remain understandable even without data.

Explain:

why nothing appears

what users should do

how to proceed

Avoid blank screens.

---

# Error Messages

Errors should:

describe the problem

explain the cause where possible

provide a solution

Avoid technical jargon unless appropriate.

---

# Defaults

Products should work well immediately after installation.

Good defaults reduce configuration effort.

Avoid requiring unnecessary setup.

---

# Accessibility

Products should remain usable by a broad audience.

Consider:

contrast

font size

spacing

keyboard navigation where applicable

colour accessibility

Accessibility improves usability for everyone.

---

# Performance

Products should remain responsive.

Avoid unnecessary calculations.

Avoid excessive automation.

Optimise for real-world hardware and internet conditions.

---

# Brand Consistency

Every product should feel like it belongs to the Studio.

Consistency should exist across:

documentation

reports

dashboards

templates

presentations

GitHub repositories

marketing materials

The objective is recognition through quality rather than branding alone.

---

# Design Review Checklist

Before release, confirm:

The interface feels uncluttered.

Visual hierarchy is clear.

Typography is consistent.

Spacing is balanced.

Navigation is intuitive.

Tables are readable.

Charts support decisions.

The product feels calm.

The product feels professional.

Nothing unnecessary remains.

---

# The Simplicity Test

Ask:

Could a first-time user understand this?

Could something be removed?

Does every visual element have a purpose?

If the answer is no, simplify.

---

# Closing Statement

Design is not decoration.

It is the disciplined organisation of information to help people think more clearly, work more effectively and trust the systems they use.

Every Studio product should demonstrate that philosophy.
